## 适用范围、三层设计及后续顺序

用于新项目和已有项目的软件工程协作，不承担编程带教。通用规则由根入口和后续 `references/` 提供；项目专属规则由模板生成到业务项目 `doc/`；跨项目知识保留在 Skill 根目录 `knowledge/`。

后续顺序为：审批规则 → 项目地图及恢复 → 编码与数据安全 → 测试体系 → 共享知识库协议 → 自检与完整说明。各模块另行提交具体地图并获得开发授权，不把本次整体设计认可当成所有阶段开发授权。

## 本模块功能地图 v1

- 目标：建立唯一活动入口，保留旧版，避免旧带教规则默认参与工程协作判断。
- 范围：主入口、仓库说明、两份历史归档、本制作记录。
- 原开发范围不涉及：详细规则文件、业务代码、依赖安装、知识库协议与条目修改、第二套知识库、自动安装、本地全局设置。后续发布授权追加当前模块的 Git 提交与推送。
- 调用关系：宿主发现根 `SKILL.md` → 加载审批与实施边界 → 有知识候选时按需读取根 `knowledge/`。`legacy/` 不参与规则加载。
- 复用：现有知识库协议的核对、去重和条目格式；排除旧协议中的带教触发、提示等级和 Git 暂存建议。
- 文件操作：替换根入口和根说明前，从 Git 基线按原始字节保存完整旧文件；新增本记录。旧文没有丢弃，没有重命名现有知识条目。
- 安全：归档不使用可发现的 `SKILL.md` 文件名，入口注明归档不作指令；不包含账号、令牌或业务隐私；不更改全局配置。
- 风险与后果：仅加 HTML 注释无法防止原始文本被 AI 读取；非入口扩展名避免标准 Skill 发现，入口规则避免主动加载，不能作为文件权限隔离承诺。
- 异常：原文无法读取、归档不一致或入口验证失败时，不继续提交或发布；保留基线和原始归档供定向修正，不覆盖知识库。
- 验收：只有一个活动入口；新名称正确；归档与基线逐字节一致；知识库零变更；现有相对链接有效；入口格式检查通过；制作范围和未执行测试据实报告。
